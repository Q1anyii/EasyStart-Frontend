阶段六之后的路线
先收尾框架层，再补工程必备，再按项目需要补 AI 前端专项，最后落到真实项目。
标签含义：必学 · 按需 · 项目
第一层 · 框架收尾
本周内
补完最后 2 课
第8课 · 组件化实战
记账本 React 重构：拆组件、state 归位、props 串通信、effect 同步持久化
第9课 · 路由 + 完整项目
React Router、多页组织、对话前端雏形（chat-stream 的 React+TS 正式版）
第二层 · 工程必备
日常开发要用
优先级最高
请求层 + 流式
fetch 封装、加载/错误态、SSE 流式响应——优先级最高，直接服务项目层
状态管理
Context 先够用，再上 Zustand 轻量方案；Redux 非必要不学
样式与组件库
Tailwind 或 Ant Design 二选一，别两套都学
构建与部署
Vite 产物、Nginx、Docker 前端镜像；读懂现有 CI/CD workflow
测试（按需）
Vitest + Testing Library 基础；有时间再补
第三层 · AI 前端专项
跟项目走
用到再学
流式对话渲染
逐字追加、中断、正在输入态
Markdown + 代码高亮
回复内容格式化渲染
会话与上下文管理
历史列表、Token 用量、多轮状态
长列表虚拟滚动
几百轮对话不卡的方案
Next.js / Vercel AI SDK
做公网产品或确实需要时再学，现阶段不急着上
第四层 · 项目落地
真实需求驱动
不再跟教程
重写一个已有前端应用
用 React + TS + 真接口 + 流式，替换现有实现
Agent 前端可视化壳
给已有 Agent 加一层可视化界面，可延后
收工判据：能独立做完一个「带路由 + 带真接口 + 带流式 + 能部署」的前端应用，前端这条路线就可以收工，回到后端/Agent 主线。
取舍原则：第二层「请求层 + 流式」最先补，它同时服务第9课、项目层与流式对话场景；样式方案只选一套；Redux / Monorepo / 微前端 / SSR 深度定制现阶段不学；测试只到"能写 3~5 个用例、讲清为什么测纯函数比测组件容易"。
